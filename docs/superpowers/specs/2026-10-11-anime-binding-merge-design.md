# 重新绑定番剧时合并已有条目（已确认）

用户于 2026-10-11 确认按推荐方案实现。

## 目标与交互

用户重新选择 Bangumi 词条时，如果该词条已被库中另一番剧占用，显示已有条目的标题和入口，并提供“合并到已有番剧”和“取消”。普通重新绑定沿用原流程；同一条目重复绑定不进入合并流程。

推荐保留已有条目的资料：稳定保留目标 ID、标题、季数、封面、导入日期和锁定状态，合并当前条目的媒体及别名。另一方案是逐字段选择保留哪份资料，操作更复杂，本次不采用；直接自动合并缺少用户确认，本次不采用。

点击合并后先生成预览，列出源/目标标题、Bangumi ID、全部媒体数量（含缺失文件）、别名数量，以及同集不同文件的数量。明确告知资料保留规则、原条目将被移除、实际文件不移动。用户确认后执行；取消不修改数据。

## 数据规则

- 所有媒体记录转移到已有条目，保留媒体 ID、原路径、整理路径、状态、来源、原始集数和人工集数。相同集数的不同文件全部保留，不做物理去重或覆盖。
- 非人工正片依据目标词条的已保存分集映射从原始集数重算；无映射时保留原始值。人工集数优先，特殊集不转换。
- 保存源标题和已有别名；别名重复时合并，人工别名优先。目标资料不被源资料覆盖。
- 保留整理历史及媒体关联，失效尚未执行的整理预览，避免按旧归属执行；已完成整理不更改文件。
- 成功后移除空的源番剧记录，新增含源/目标 ID 和标题的合并审计，并转到目标详情页。保留原历史审计，不伪造旧记录。
- 锁定的源条目拒绝合并，锁定的目标可接收媒体但资料保持不变。

## 接口与一致性

新增明确的预览与确认 DTO。服务端先查目标词条实际所有者，不信任客户端传来的目标信息。预览只读，返回预览摘要/版本；确认时在事务中重新验证源/目标存在、当前绑定、锁定状态和预览版本。状态已变化则返回稳定冲突错误并要求重新预览。媒体转移、别名处理、预览失效、源记录移除和审计必须整体成功或回滚。

绑定冲突响应提供目标 ID，前端据此展示合并入口。所有 UI 请求继续使用现有本地来源校验；异步回包需验证当前详情代次，避免操作其他番剧。
