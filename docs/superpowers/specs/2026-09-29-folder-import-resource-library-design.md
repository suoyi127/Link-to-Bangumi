# 资源库与文件夹导入设计

## 目标

将现有侧栏“待整理”改为“资源库”，保留 qB 下载与项目内 `Media/Import` 两条来源，并增加并列的“文件夹导入”。文件夹导入允许用户在页面填写本机已有目录的绝对路径，登记后只读扫描其中视频；不复制、移动或删除原文件。网页浏览器不能向后端透露本机目录的真实路径，所以普通网页版本先使用路径输入框，不伪装为系统文件夹选择器。

## 方案比较

- 推荐：登记原目录并扫描。无额外视频副本，复用现有解析、整理预览和刮削；需要持久化目录、隔离各次扫描并在播放/整理时重新验证路径。
- 复制整夹到 `Media/Import`。安全模型较简单，但大体积视频占用双份空间，且会与“外来导入”混淆。
- 仅加一个第三个固定目录。实现容易，但并不能从用户任意现有文件夹导入。

## 数据与接口

新增有序数据库迁移：`folder_import` 保存规范化后的绝对根路径，`media_file.folder_import_id` 标记该来源。为兼容既有 SQLite `origin` 约束，底层 `origin` 仍存 `external_import`，API/业务模型把带 `folder_import_id` 的记录呈现为独立的 `folder_import` 来源。qB 与固定外来导入记录不受影响。

新增 `GET /api/folder-imports` 列出已登记目录、`POST /api/folder-imports` 登记 `{path}`、`POST /api/folder-imports/{id}/scan` 扫描指定目录。登记要求本机绝对目录、非磁盘根、与 qB/固定导入/媒体库及其他已登记目录互不包含；路径会 canonicalize，并限制长度。目录不可用或被替换时返回稳定错误码，不清理既有媒体。扫描复用 `DirectoryScanner`，只在当前文件夹范围内更新缺失状态，不影响其他文件夹或来源。扫描完成后按现有流程触发 Bangumi 自动刮削。

整理预览、执行和本机播放通过媒体记录关联的登记根目录检查源路径；仍使用原有快照、冲突检查和确认流程。qB 的“已下载完成”确认只用于 qB 来源。文件夹导入根目录的删除/修改不是本阶段功能，避免已有记录失去安全边界。

## 界面

侧栏与页标题显示“资源库”。资源库顶部为“qB 下载”“外来导入”“文件夹导入”三个并列标签。第三标签提供绝对路径输入、添加按钮、已登记目录列表、逐目录扫描按钮和该来源的待整理文件列表。qB/外来导入沿用已有整理操作。仪表盘可继续提供两条原有扫描快捷入口；文件夹导入从资源库操作。

## 验证

先用临时目录的集成测试证明：两个登记文件夹不会互相标记缺失；重扫能更新本文件夹已消失的文件；重叠路径被拒绝；文件夹来源可预览/整理/播放且目录外路径被拒绝。再运行后端构建和相关测试、前端测试与构建。不会触碰 `D:/追番` 的真实媒体文件。
