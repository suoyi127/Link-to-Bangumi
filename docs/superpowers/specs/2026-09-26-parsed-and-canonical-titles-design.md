# 识别标题与规范标题分离

## 目标

从下载后的媒体文件名提取识别标题与集数，并允许用户将该识别标题映射到一个规范番剧标题。命名组和 RSS 标题都不作为本地文件标题来源；解析输入始终是扫描到的实际文件名。

## 设计

- `media_file.parsed_title` 保存扫描器从实际文件名解析出的稳定标题，作为识别标题，不被后续人工修正覆盖。
- `media_file.title` 继续表示当前整理预览标题。首次扫描时它等于识别标题；用户确认修正后它等于用户输入的规范标题。
- 用户确认标题修正时，旧识别标题写入当前番剧的 `anime_alias`（source=`user`）；规范标题作为 `anime.display_title`。已有规范标题若被用户明确改名，旧显示标题也保留为用户别名。
- 自动扫描遇到别名时继续把媒体关联到已有 `anime_id`，但不改写番剧的 `display_title`。
- 整理预览使用已关联番剧的 `display_title`；无番剧关联时退回 `media.title`。
- 目标仍位于规范标题目录下，正片文件名为 `规范标题 [01].mkv`。特殊类型保留类型标记，例如 `规范标题 [SP01].mkv`、`规范标题 [OVA01].mkv`、`规范标题 [NCOP01].mkv`、`规范标题 [NCED01].mkv`。
- 解析器继续使用通用首个方括号发布组与集数规则，不对 `Sakurato`、`ANi` 等字幕组名硬编码。清理标题尾部的句点等发布分隔标点；已识别文件扩展名不进入标题。
- Bangumi 绑定提供的正式名/中文名继续加入别名；绑定本身仍要求用户显式确认，不自动通过模糊相似度绑定。

## 数据兼容与安全

新增有序 SQLite migration，为现有记录初始化 `parsed_title` 为当时的 `media_file.title`；旧记录原始文件名仍保留在 `filename`。自动扫描、用户修正、别名写入、番剧重命名须在 repository 事务内保持一致。已有目标路径冲突仍由预览报告，不覆盖文件；本变化不会搬动已整理文件。

## 验收

- `[Sakurato] Toumei na Yoru ni Kakeru Kimi to, Me ni Mienai Koi o Shita. [01][AVC-8bit 1080P AAC][CHS].mkv` 解析出识别标题 `Toumei na Yoru ni Kakeru Kimi to, Me ni Mienai Koi o Shita`、集数 `01`、发布组 `Sakurato`。
- 用户把首集规范标题修为 `与奔驰于透明之夜的你，谈一场看不见的恋爱` 后，识别标题作为 alias，后续同罗马音标题的扫描可关联到该规范番剧。
- 关联后的整理预览目标为 `媒体库/与奔驰于透明之夜的你，谈一场看不见的恋爱/与奔驰于透明之夜的你，谈一场看不见的恋爱 [01].mkv`。
- 未关联媒体沿用其 `media.title` 形成目标；源路径校验、冲突预览、幂等执行和 qB 完成声明保持现有行为。
- 数据库、解析器、规划器与管理 API 的测试均使用 disposable SQLite/目录，不触碰 `D:\追番`。
