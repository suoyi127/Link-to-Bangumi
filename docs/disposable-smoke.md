# 阶段 0–5 临时目录冒烟核验（Windows）

此流程只使用一次性目录，不写入真实 `D:\追番`。先编译后端、安装前端依赖。所有终端都在仓库根目录运行。

1. 新建四个互不嵌套的临时目录：`source`、`imports`、`library`、`data`。在 `source` 放一个仅用于核验的小文件，例如 `Example.S01E01.mkv`。不要使用真实番剧。设置 `ANIME_VAULT_SOURCE_DIR`、`ANIME_VAULT_IMPORT_DIR`、`ANIME_VAULT_LIBRARY_DIR`、`ANIME_VAULT_DATA_DIR` 为这四个绝对路径；不要设置 Bangumi User-Agent。启动 `anime_vault_server.exe`，确认 `/health` 返回 `status: ok`。
2. 启动 `npm.cmd --prefix frontend run dev` 并打开 Vite 打印的地址。确认仪表盘可显示健康状态、设置页显示四个临时路径，Bangumi 为未配置、qB Web UI 为未启用。
3. 点击“扫描 qB 来源”一次，等待至少 60 秒后再次点击。扫描器要求文件修改时间和首次观察时间都稳定满 60 秒；两次扫描相隔不足 1 秒也会被限流。确认文件出现在待整理列表、来源为 `qb_download`。
4. 在收件箱修正标题/季/集数/类型并保存。选择硬链接生成预览，核对目标在临时 `library` 内且无冲突。勾选独立的“qB 下载已完成”声明，打开确认框，再确认执行。若计划过期，重新生成预览；重试同一计划时必须复用幂等键。
5. 确认待整理列表更新、番剧库可打开对应详情，媒体文件状态与路径可见，临时 `source` 文件仍在；目标硬链接位于临时 `library`。设置页审计记录可查看。Bangumi 未配置时搜索报稳定错误，但本地详情仍可用。

外来导入可选核验：在临时 `imports` 放另一小 `.mkv` 文件，点击独立的“扫描外来导入”按钮两次（同样相隔至少 60 秒）；预览和执行不需要 qB 完成声明。不要把 qB 来源文件复制到导入目录来模拟真实来源。

结束后先关闭两项服务。仅在再次核实临时根目录确为本次创建、且不包含任何个人媒体后，删除该临时目录。不得把 `D:\追番` 作为清理目标。
